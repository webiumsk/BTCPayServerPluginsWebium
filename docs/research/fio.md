# Fio banka token API - research notes

Primary source: **Fio API Bankovnictví v1.9** (16. 10. 2025),
<https://www.fio.cz/docs/cz/API_Bankovnictvi.pdf> (read 2026-08-01; linked
from fio.sk "API bankovníctvo"). The API is free ("poskytována zdarma").

## Token

- Generated by the account owner in internetbanking: Nastavení → API →
  "Přidat nový token"; creation requires strong authorization (SMS/push),
  usable **5 minutes** after authorization. 64-character string.
- One token = one account. Two permission scopes - use **"Pouze sledovat
  účet"** (read-only export) for this plugin.
- Validity: mandatory, max **180 days**; optional automatic renewal
  extends it to 180 days from every internetbanking login.
- Data older than 90 days need a temporary unlock in internetbanking
  (not relevant for polling).

## REST endpoints (base `https://fioapi.fio.cz/v1/rest`)

- `GET /last/{token}/transactions.json` - movements since the server-side
  cursor ("zarážka"); the cursor advances automatically whenever the
  response contains movements. **The cursor is per token** - the token
  must be dedicated to one consumer.
- `GET /periods/{token}/{yyyy-mm-dd}/{yyyy-mm-dd}/transactions.json` -
  period query; does not move the cursor (used for the Test button).
- `GET /set-last-id/{token}/{id}/`, `GET /set-last-date/{token}/{date}/` -
  manual cursor resets (recovery only).
- Rate limit: recommended **minimum 30 seconds** between requests per
  token regardless of format; HTTP 409 Conflict when violated. Other
  documented errors: 404, 413 (too many items), 422, 500.

## JSON movement columns (5.3.1.6)

`accountStatement.info` carries accountId/bankId/currency/**iban**/bic and
cursor ids (`idLastDownload`). `transactionList.transaction[]` cells are
`{"columnN": {"value": ..., "name": ..., "id": N}}` (null when absent):

| Column | Meaning |
|---|---|
| column22 | ID pohybu (unique movement id - dedup key) |
| column0 | date |
| column1 | amount (positive = credit) |
| column14 | currency (ISO 4217) |
| column2/column3/column26 | counterparty account / bank code / BIC |
| column4 / column5 / column6 | KS / **VS** / SS |
| column7 | user identification |
| column16 | message for the recipient |
| **column27** | **Reference plátce** - "bližší identifikace platby dle ujednání mezi účastníky platby" (carries the SEPA end-to-end id) |
| column8 | movement type (41 = Okamžitá příchozí platba, 44 = Okamžitá příchozí Europlatba) |

## Plugin mapping (v0.6)

Reference resolution order: column27 (e2e) → column5 (VS, CZ profile) →
`QR-[0-9a-f]{32}` extracted from column16. Credits only (column1 > 0);
dedup key `fio:{column22}`; currency check happens in SepaMatchingService.
Poll tick 60 s (only stores with pending requests), 409 treated as
"skip this tick". Whether the payer's bank propagates the e2e reference
into column27 for instant SEPA credits must be confirmed with a live
end-to-end test - the VS and message fallbacks cover the gap.
